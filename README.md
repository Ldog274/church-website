# East Side Free Will Baptist Church

Static site for East Side Free Will Baptist Church, Muldrow, Oklahoma.
Hosted free on GitHub Pages at <https://eastsidefwbc.org/>.

## How it is published

Every push to `main` updates the live website within about a minute. There is no build step,
no framework and no dependencies - just HTML and one CSS file.

- `index.html` - home: welcome, service times, the map, and ways in
- `about.html` - about us, our pastors, planning a visit (history draft withheld until completed)
- `beliefs.html` - the gospel in short, then what we teach and preach
- `ministries.html` - children, students, adults, care ministries, community outreach
- `calendar.html` - church calendar
- `sermons.html` - watch a service and find a message
- `give.html` - giving
- `contact.html` - contact details and a message form
- `404.html` - shown for a bad URL
- `css/styles.css` - all styling, one file
- `assets/img/` - photographs, with credits in `assets/img/CREDITS.md`
- `assets/img/social-card.jpg` - the picture shown when a page is shared
- `favicon.svg`, `favicon.ico`, `apple-touch-icon.png` - the tab and home-screen icon
- `sitemap.xml`, `robots.txt` - for search engines. Both are generated; see below
- `CNAME` - the custom domain. GitHub manages this file; do not edit or delete it.

## Editing

Edit the file, commit, push. That is the whole workflow.

```bash
git add -A && git commit -m "Update service times" && git push
```

The pages were generated by `tools/build_site.py`. Editing the HTML by hand is perfectly fine -
they are plain HTML - but be aware that re-running the generator rebuilds every page,
`sitemap.xml` and `robots.txt` from scratch, so any hand edit not reflected in the generator
will be overwritten. When in doubt, edit the generator and run it:

```bash
python tools/build_site.py
```

The generator writes into the folder given by `D` at the top of the file, so point that at
this repository before running it.

## The calendar

`calendar.html` is ready to be wired to the church's Google Calendar, so events added there
appear on the site automatically. To switch it on:

1. In Google Calendar, hover the church calendar, open **Settings and sharing**.
2. Under *Access permissions for events*, tick **Make available to public**.
3. Under *Integrate calendar*, copy the **Calendar ID**.
4. In `calendar.html`, replace `YOUR_CALENDAR_ID` in the commented-out iframe, delete the
   comment marks around that iframe, and delete the `callout--quiet` block beneath it.

The calendar must be public or the embed will not render, and only events on that calendar
are shown - so keep private appointments on a separate calendar.

## The message form on the contact page

The site is plain static hosting, so there is no server to receive a form. The form on
`contact.html` therefore composes an email in the visitor's own email program, addressed to
`eastsidefwbc@gmail.com`, and confirms on screen when it has done so. Nothing is stored on
the site, and there is no third party in the middle.

The trade-off: a visitor whose device has no email program set up will not be able to send
through the form. The page says so plainly and gives the church email address and phone
number instead. If a form that always works is wanted later, that needs an outside form
service (Formspree and similar), which would mean prayer requests passing through and being
stored by another company - worth deciding deliberately.

## Privacy and third parties

The site loads no fonts, scripts or analytics from third-party servers. Two elements are
Google's, and they only load when the visitor scrolls to them:

- the Google Map on the home page
- the Google Calendar on `calendar.html`, once enabled

Both set Google's own cookies when they load.
